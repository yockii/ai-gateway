**Objective:** Establish comprehensive Go integration testing infrastructure using testcontainers for real PostgreSQL and Redis dependencies, enabling reliable API and database testing without mocks.

**Purpose:** Integration tests with real dependencies catch issues that unit tests miss (ORM behavior, transaction isolation, connection pool behavior). Using testcontainers ensures tests run identically across local and CI environments.

**Output:** Working integration test suite that validates API handlers, database operations, and migrations against real containers.

## <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test code → production database | Tests MUST use isolated containers, never production |
| CI environment → Docker daemon | CI needs Docker access for testcontainers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | testcontainers | mitigate | Use isolated test databases with unique names per test |
| T-04-02 | Tampering | test data | mitigate | Each test creates fresh data, cleanup on t.Cleanup() |
| T-04-03 | Information Disclosure | test logs | mitigate | Sanitize sensitive data in test logs, no real API keys in tests |
| T-04-04 | Denial of Service | container leaks | mitigate | Use t.Cleanup() guarantee, set container resource limits |
| T-04-05 | Escalation | test database access | accept | Test containers run locally/CI, no external access |
</threat_model>

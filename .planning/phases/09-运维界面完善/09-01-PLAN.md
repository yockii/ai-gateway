## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 浏览器 → API Gateway | 未信任的客户端请求，需要 JWT 认证 |
| Admin → Backend API | 管理员操作，需要记录审计日志 |
| SSE Connection | 长连接，需要认证和授权验证 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Spoofing | 所有 Admin API | mitigate | JWT 认证中间件验证所有请求 |
| T-09-02 | Tampering | API Key 更新 | mitigate | 使用字段白名单，防止 mass assignment |
| T-09-03 | Repudiation | 敏感操作 | mitigate | 审计日志记录所有变更，包含操作人、时间、IP |
| T-09-04 | Information Disclosure | API Key 显示 | mitigate | 后端仅返回 key_prefix，完整密钥仅在创建时显示一次 |
| T-09-05 | Denial of Service | SSE 连接 | mitigate | 限制每个管理员的并发 SSE 连接数，设置超时 |
| T-09-06 | Elevation of Privilege | 路由访问 | mitigate | 验证 admin_id 是否有权限操作指定的 supplier_id/customer_id |
| T-09-07 | Tampering | 审计日志 | mitigate | 审计日志写入后不可修改，仅追加 |
| T-09-08 | Information Disclosure | 变更历史 | accept | Changes 字段可能包含敏感数据，但仅管理员可访问 |
| T-09-09 | XSS | 前端显示 | mitigate | Vue 自动转义，避免 v-html 显示用户输入 |
| T-09-10 | CSRF | 状态变更操作 | mitigate | JWT 在 Authorization 头中，SameSite cookie 配置 |

## Security Notes

1. API Key 加密存储由 internal/crypto.EncryptionService 处理
2. 所有审计日志异步记录，使用 goroutine 避免阻塞主流程
3. SSE 连接需要 JWT 认证，在建立连接时验证
4. 前端不缓存敏感数据（如完整 API Key）
